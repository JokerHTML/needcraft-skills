# Feedback log — template + filled example

Keep the log in one file at a path you choose (for example `feedback-log.md` in your
product folder). One entry per feedback item, including NO ACTION items with the reason.
The log is internal, never customer-facing. The filled entry below is illustrative,
written for this skill — not a real customer's words.

## Blank template

```
DATE: YYYY-MM-DD | SOURCE: email / comment / review / refund request / DM
VERBATIM: "[customer's exact words — short quote]"
CLASS: QUESTION / CONFUSION / OBJECTION / BUG / MISSING CONTENT / EXPECTATION GAP / FEATURE REQUEST / POSITIVE SIGNAL / REFUND SIGNAL
ROOT CAUSE: [product / listing copy / onboarding / missing file / wrong expectation — one line]
ACTION: PRODUCT FIX / FAQ FIX / CONTENT IDEA / SALES PAGE FIX / ONBOARDING FIX / NO ACTION
STATUS: open / done
VERIFIED: [yes — how you re-tested the exact scenario | no — still open, why]
```

## Filled example entry

```
DATE: 2026-11-16 | SOURCE: email
VERBATIM: "I can't find the templates — where are they?"
CLASS: CONFUSION
ROOT CAUSE: onboarding — the contents page does not point to page 6, where the templates live
ACTION: ONBOARDING FIX
STATUS: done
VERIFIED: yes — opened the updated file, followed the contents page, reached the templates in 2 clicks
```

## A second filled example (refund signal)

```
DATE: 2026-11-16 | SOURCE: email
VERBATIM: "This isn't what I expected — can I get my money back?"
CLASS: REFUND SIGNAL
ROOT CAUSE: expectation gap — the listing's headline implied done-for-you writing; the product is templates
ACTION: SALES PAGE FIX (rewrote the headline to say "templates you customise") + fix-first refund offered per the stated terms
STATUS: done
VERIFIED: yes — re-read the full listing against the product files; refund processed under the 30-day fix-first terms; customer confirmed receipt
```
